# 企画書：alt評価ツール（仮称）

## 概要

Webページの画像に付いているalt属性を、ページを閲覧しながら「良い・普通・悪い」の3択で評価し、ページと画像の情報とあわせて記録するChrome拡張機能です。記録はファイルに書き出して他の人と共有でき、取り込んだ記録とあわせて一覧で見られます。

全盲のエンジニアとの会話から出てきたアイデアです。良いaltと良くないaltの実例を集めて共有すれば、「どういうaltが良いのか」を具体例で示せるようになります。

altの良し悪しは、画像が置かれた文脈で変わります。同じ「矢印」というaltでも、装飾の画像なら不要な読み上げになり、次のページへ進むリンクの画像なら情報が足りません。そのため、評価はページから切り離した一覧ではなく、ページの中の画像のすぐ近くで行います。

最初の版では、記録の共有はJSONファイルの書き出しと取り込みで行います。共有用のサーバーは作りません。サーバーを用意すると、アカウント管理、個人情報の扱い、運用の費用が必要になり、今日のワークの範囲に収まらないためです。

## 解決したい課題

- altの書き方の解説は「画像の内容や役割を簡潔に伝える」のような一般論になりやすく、具体的なaltを見て良し悪しを判断する練習の機会が少ない
- 同じaltでも、ページの文脈によって良し悪しが変わる。文脈とセットの実例が手元に残らない
- スクリーンリーダーの利用者が「このaltはわかりやすい」「このaltは困る」と感じても、その評価を記録して他の人に渡す手段がない

## 使う人

- **評価する人：** スクリーンリーダーの利用者、アクセシビリティの専門家、Web制作者など。評価する人の立場は問いません
- **記録を見る人：** altの書き方を学びたい制作者、社内やコミュニティでaltの基準を話し合いたい人

全盲の人が評価できることを前提にします。そのため、評価の操作はキーボードとスクリーンリーダーだけで完結するようにしてください。

## 使い方の流れ

1. 評価したいページを開き、ツールバーのボタンかキーボードショートカットで評価モードをオンにします
2. ページ内の各画像の直後に、評価ボックスが表示されます。評価ボックスには、altの内容と「良い・普通・悪い」の3つのボタンがあります
3. ページを読み進めながら、画像ごとにボタンを押して評価します。押した評価は、その場で保存されます
4. 評価モードをオフにすると、評価ボックスが消え、ページが元の表示に戻ります
5. 記録の一覧（設定画面）で、これまでの記録を見たり、評価で絞り込んだりします
6. 記録をJSONファイルに書き出して、他の人に渡します。受け取った人は、そのファイルを取り込みます

## 評価ボックス

### 置き場所

評価ボックスは、各 `img` 要素の直後に挿入します。画像の上に重ねて表示する方法と比べた結果は、次のとおりです。

| 利用場面 | 画像の直後に挿入する | 画像の上に重ねて表示する |
|---|---|---|
| 晴眼者・マウス | 画像の真下にaltが見え、そのままクリックで評価できる | 画像の上にaltが見える。画像の一部が隠れてしまう |
| スマホ・タッチ | 画像の真下にボタンがあり、タップで評価できる | 小さな画像ではボタンが重なり、押し間違えやすい |
| キーボード | Tabキーで、画像の順番どおりにボタンへ移動できる | 重ねた要素をページの末尾に置くため、Tabキーの移動順が画像の並びと一致しない |
| スクリーンリーダー | 画像を読み上げた直後に評価ボックスが読み上げられる | 評価ボックスがページの末尾にあり、どの画像のボックスかわからない |

画像の直後に挿入すると、ページのレイアウトが崩れる場合があります。評価モードの間だけの表示なので、レイアウトの崩れは許容します。

`img` 要素がリンクやボタンの中にある場合は、リンクやボタンの中にボタンを置けないため、リンクやボタンの直後に挿入します。

### 表示する内容

評価ボックスの1行目にaltの状態を、2行目に3つのボタンを表示します。

| altの状態 | 1行目の表示 |
|---|---|
| alt属性あり | alt：（altの全文） |
| 空のalt（`alt=""`） | 空のaltの画像 |
| alt属性なし | alt属性なし（ファイル名が読み上げられる場合があります） |

altは省略せずに全文を表示します。途中で切ると、長すぎるaltを「悪い」と判断できなくなってしまうためです。altの状態は、色だけで区別せず、文字で示します。

評価ボックスの見た目はシャドウDOMの中で作り、ページのCSSの影響を受けないようにします。

### スクリーンリーダーでの読み上げ

スクリーンリーダーは画像のaltを自分で読み上げます。そのため、評価ボックスの中でもaltを読み上げると、同じaltが2回続けて読まれてしまいます。altの状態ごとに、評価ボックスの1行目を次のように扱います。

| altの状態 | 画像自体の読み上げ | 評価ボックスの1行目 |
|---|---|---|
| alt属性あり | altが読み上げられる | 読み上げない（`aria-hidden="true"`）。画面には表示する |
| 空のalt | 読み上げられない | 読み上げる。画像があることを伝えるため |
| alt属性なし | ファイル名などが読み上げられる場合がある | 読み上げる。altが無いことを伝えるため |

3つのボタンは、「直前の画像のaltの評価」という名前のグループにまとめます。この名前にaltは含めません。altを含めると、ページを順に読んだ時にaltが2回読まれてしまうためです。ただし、Tabキーでボタンへ直接移動した利用者には、どの画像のボタンかが伝わりにくくなります。この点は、スクリーンリーダーの利用者に使ってもらってから見直します。

### ボタンの動き

- 3つの評価は、押した状態を示すボタン（`aria-pressed`）にします。ラジオボタンにすると、矢印キーで選択が変わるたびに保存が実行され、「良い」から「悪い」へ移動する途中で「普通」の保存が入ってしまうためです
- 押した評価は、ボタンの押した状態で示します。画面では色と形（チェックの記号）の両方で示します
- 「保存しました」の読み上げは、ボタンの押した状態の変化と重複するので加えません。保存に失敗した時だけ読み上げます
- ボタンの大きさは44×44px以上にします
- 押した評価をもう一度押すと、評価を取り消します
- 評価を押すと、3つのボタンの後ろにメモの入力欄が表示されます。フォーカスはボタンに残したまま移動させず、メモを書きたい人だけがTabキーで入力欄へ進みます。評価しただけの画像では入力欄を表示しないので、Tabキーの移動先が増えません

## 機能

### 最初の版で作るもの

- **評価モードのオン・オフ：** ポップアップのボタンとキーボードショートカット（`chrome.commands`）で切り替える。ポップアップには、ページ内の画像の数と評価済みの数も表示する
- **評価ボックス：** 各画像の直後に、altの状態と3つのボタンを表示する
- **メモ（任意）：** 評価の理由を短く書ける
- **記録の保存：** 評価をブラウザの中（`chrome.storage.local`）に保存する。評価済みのページで評価モードをオンにすると、保存した評価が押した状態で表示される
- **記録の一覧（設定画面）：** 記録を表で表示し、評価・ページで絞り込む。記録を削除できる
- **書き出しと取り込み：** 記録をJSONファイルで書き出す。他の人のJSONファイルを取り込み、自分の記録と区別して表示する

メモは、最初の版に含めることをおすすめします。共有した記録を見る人にとって、「悪い」という評価だけでは直し方がわからず、理由があると学べる内容が増えるためです。

評価モードは、ページを移動するとオフに戻ります。`activeTab` 権限の許可が、ページを移動した時点で切れるためです。

### 最初の版では作らないもの

- スマホでの評価（下の「スマホへの対応」を参照）
- 共有用のサーバー、アカウント、ランキング
- `img` 要素以外の画像（CSSの背景画像、`svg` 要素、`role="img"` を付けた要素、`input type="image"` など）
- 画像そのもののデータの保存（画像のURLだけを記録する）
- 評価の集計やグラフ

## スマホへの対応

Android版とiOS版のChromeでは、拡張機能を使えません。そのため、Chrome拡張機能のままでは、スマホで閲覧しながらの評価はできません。

画像の直後に評価ボックスを置く設計は、タッチ操作やスマホのスクリーンリーダー（VoiceOver、TalkBack）でも、画像と同じ順番で操作できます。Firefox for Androidのアドオンや、Safariの拡張機能へ移植する時も、この設計をそのまま使えます。最初の版はパソコンのChromeだけを対象にし、スマホへの対応は次の段階で検討します。

## 記録する項目

| 項目 | 内容 |
|---|---|
| ページのURL | 評価したページのURL |
| ページのタイトル | `document.title` |
| 画像のURL | `img` 要素の `currentSrc`（無ければ `src`） |
| altの状態 | 「alt属性あり」「空のalt（`alt=""`）」「alt属性なし」のどれか |
| altの内容 | alt属性の文字列 |
| リンク先のURL | 画像がリンクの中にある場合だけ記録する |
| 評価 | 良い・普通・悪い |
| メモ | 評価の理由（任意） |
| 評価した日時 | 保存した日時 |
| 評価した人 | 書き出す時に入れる名前（任意） |

空のaltとalt属性なしは、区別して記録します。装飾の画像なら空のaltが「良い」になり、意味のある画像に空のaltが付いていれば「悪い」になります。

リンク先のURLを記録するのは、リンクの中の画像では、altがリンク先を伝える役割を持つためです。記録を見る人が、altとリンク先を見比べて評価の理由を理解できるようにします。

## 権限（permissions）

| 権限 | 必要な理由 |
|---|---|
| `activeTab` | 評価モードをオンにした時だけ、表示中のタブのページに評価ボックスを挿入するため。すべてのサイトを読む権限（`host_permissions`）は付けません |
| `scripting` | `activeTab` で許可されたタブに、評価ボックスを挿入するスクリプトを実行するため |
| `storage` | 評価の記録を拡張機能の中に保存するため |

ファイルの書き出しは、ダウンロード用のリンクを作る方法で行い、`downloads` 権限は使いません。

## アクセシビリティ

評価ボックスの読み上げとボタンの動きは「評価ボックス」の節に書きました。それ以外の画面（ポップアップ、記録の一覧）では、次の点を守ります。

- 操作をすべてキーボードで行えるようにする
- 画面の構造を見出しやリストで示す
- 背景と文字のコントラスト比を4.5対1以上、ボタンなどの境界線と背景を3対1以上にする
- 記録の一覧の表は、`table` 要素と見出しのセルで作る

## 共有するときの注意

ページのURLには、社内のサイトのアドレスや、URLの後ろに付いた検索語・ログインの情報などが含まれることがあります。書き出す前に、書き出す記録の一覧を表示して確認できるようにします。

画像のURLは記録しますが、画像そのものは保存しません。共有した相手は、画像のURLを開いて画像を見ることになります。そのため、元のページから画像が消えると、共有した記録でも画像を見られなくなってしまいます。

## 決めていないこと

- **ツールの名前：** 今は「仮の名前」です
- **「良い・普通・悪い」の基準：** 最初の版では評価する人の判断に任せます。基準の例を画面に出すかどうかは、使ってみてから決めます
- **URLの扱い：** 書き出す時に、URLの `?` 以降を自動で削るかどうか
- **文脈として記録する情報：** リンク先のURLのほかに、画像の直前の見出しや周りの文章を記録するかどうか
- **対象にする画像の範囲：** `display: none` で隠れている画像、カルーセルの非表示の画像、`iframe` の中の画像を含めるかどうか
- **画像の多いページでの移動：** 評価ボックスに「次の未評価の画像へ」のボタンを付けるかどうか
- **共有の次の段階：** JSONファイルの受け渡しの次に、GitHubのリポジトリに記録を集める、共有用のサーバーを作る、などの方法をどうするか
